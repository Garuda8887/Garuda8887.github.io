whisperdrop View repo ↗

A burn-after-reading pastebin where the server never sees the plaintext — it can't decrypt what it stores even if it wanted to.

encrypt in browser → ciphertext + IV → server → key rides in URL #fragment → burn on read
  1. Browser generates a random AES-256-GCM key and encrypts the text locally, via the Web Crypto API
  2. Only ciphertext and an IV are sent to the server — the key itself never leaves the browser
  3. The share link carries the key after a # — URL fragments are never sent in HTTP requests, so it never touches a server log
  4. Opening the link decrypts locally, then the server deletes the paste immediately — a second visit returns "not found"

The hard part wasn't the encryption — it was designing the server to be provably unable to help, not just promising not to.

Noctua View repo ↗

An offline attack-surface management tool built for air-gapped and confidential pentest engagements — network topology never leaves the machine.

Nmap scan → deterministic checks (EOL / creds / KEV) → local LLM synthesis (map-reduce) → interactive HTML report
  1. Ingests an Nmap scan (or runs one directly) against the target subnet
  2. A deterministic engine flags end-of-life software, default credentials, and known-exploited vulnerabilities against locally cached feeds
  3. A local Ollama model synthesizes the findings into attack narratives, using map-reduce chunking so enterprise-sized scans don't overrun a small local context window
  4. Everything renders into a self-contained, interactive HTML network graph — no cloud call at any step

The constraint that shaped everything: a local LLM's context window is small, but a real engagement's attack surface isn't — the map-reduce step exists because the network doesn't get smaller to fit the model.

Recall View repo ↗

Anki's spaced-repetition algorithm, wrapped in a calendar you actually want to open — because a scheduler only works if you show up to it.

log session + rating → SM-2 reschedules → calendar / forgetting curve / graph → stays visible, auto catch-up
  1. Log a study session — topic, subject, and a confidence rating from Blank to Perfect
  2. SM-2 reschedules the next review from that rating and a per-topic ease-factor, not a fixed interval
  3. The session lands on a month-view calendar, feeds a per-topic forgetting-curve chart, and links into a knowledge graph of related sessions
  4. Missed reviews stay visibly overdue instead of vanishing; recurring topics auto-generate catch-up instances so nothing quietly falls off the schedule

Anki already has the SM-2 math — that part's a solved problem. The actual work was building a schedule someone wants to open, since a spaced-repetition system is only as good as whether you show up to it.
